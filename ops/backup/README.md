# Wishkr encrypted backups

The OVH production host creates daily client-side encrypted backups with
restic. Cloudflare R2 is the off-provider repository. OVHcloud's included
Backup Storage is a second destination and is configured separately over
FTPS; plain FTP and NFS are not used.

The backup contains:

- a PostgreSQL custom-format logical dump, validated with `pg_restore --list`;
- a Redis RDB generated by a successful `BGSAVE`;
- `/etc/wishkr`, Nginx configuration, WireGuard configuration, and the active
  immutable application release.

Secrets and database contents are protected by restic encryption before they
leave the host. The repository password must be kept in the approved password
manager outside the OVH account.

The OVH secondary destination uses explicit FTPS on port 21 with TLS
certificate verification enabled. The plain `ftpback-*.ip-*.net` hostname is
converted to OVH's `ftpback-*.mybackup.ovh.ca` TLS hostname. NFS, CIFS, plain
FTP, and certificate-verification bypasses are not used.

Because the restic `rclone:` streaming adapter is not reliable on OVH's FTP
backend, the host maintains the OVH repository at
`/var/lib/wishkr/backup/ovh-restic-repository`. This repository is already
client-side encrypted. After each successful local snapshot and retention
pass, `rclone sync` transfers only encrypted repository objects over FTPS and
then downloads the remote objects for content comparison. Recovery drills
download the remote repository and run restic's cryptographic data
verification locally.

## Schedule and retention

`wishkr-backup.timer` runs daily at 02:15 UTC with up to ten minutes of random
delay. The policy retains 7 daily, 5 weekly, 12 monthly, and 3 yearly
snapshots. The timer is persistent, so a missed run executes after the host
returns.

## Commands

Run a backup manually:

```bash
sudo systemctl start wishkr-backup.service
sudo journalctl -u wishkr-backup.service --since today --no-pager
```

Verify backup freshness (maximum age 30 hours):

```bash
sudo /usr/local/sbin/wishkr-backup-status
```

`wishkr-backup-monitor.timer` runs this verification hourly and writes a
non-zero service result to the systemd journal if the last successful backup
is stale, the daily timer is inactive, the previous backup service failed, or
the recorded PostgreSQL, Redis, or encrypted OVH repository size is invalid.
External alert delivery is configured separately under migration Item 12.

Run the isolated R2 restoration drill:

```bash
sudo /usr/local/sbin/wishkr-test-backup-restore r2
sudo /usr/local/sbin/wishkr-test-backup-restore ovh
```

The drill verifies all repository data, restores the latest encrypted snapshot
to a temporary root-only directory, validates artifact checksums, validates the
Redis RDB in a network-isolated disposable container, and restores PostgreSQL
into a uniquely named scratch database. The scratch database and restored
files are removed on exit; the production database is never overwritten.

List encrypted snapshots without exposing credentials:

```bash
sudo bash -c 'set -a; source /etc/wishkr/secrets/r2-backup.env; set +a; restic snapshots --compact'
```

Never print, commit, or copy the contents of `/etc/wishkr/secrets` into logs,
tickets, chat, or shell history.

The total-loss procedure is maintained outside the host in
[`docs/OVHCLOUD_BARE_METAL_RECOVERY_RUNBOOK.md`](../../docs/OVHCLOUD_BARE_METAL_RECOVERY_RUNBOOK.md).
